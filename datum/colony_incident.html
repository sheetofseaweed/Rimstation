colony_incident
/datum/colony_incident

The shape every colony incident has, whatever it is about.

A raid, a trader, a storm and a dispute have almost nothing in common as content and everything in common as structure: each is announced before it lands, runs for a while, is decided, and leaves a record. Writing that once means the storyteller and the pacing state deal with one contract rather than five.

The incident is deliberately not a /datum/round_event. The event system owns when something happens and is rebuilt every round; an incident owns what happens and is chosen by the campaign from what the colony has been through. /datum/round_event/colony_incident is the join between them, so an incident stays testable without scheduling one.

Two rules the state machine exists to enforce:

  • The warning cannot be skipped. It is the colony's chance to prepare, and an incident that lands without one is a punishment rather than a story.
  • Resolution happens once. Something that resolves twice would pay its rewards twice, so the first resolution wins and later ones are refused.

ask_colony
(title, content, /list/answers, callback_proc)

Puts a question to the colony, wherever this incident allows it to be answered.

Returns TRUE if it reached somebody. A question nobody can be asked is worth knowing about immediately, so the incident can decide what happens in the absence of an answer rather than waiting out a timer.

proc
can_begin
()

TRUE when this incident could run right now.

Overridden by concrete incidents to state their own requirements - a trader needs somewhere to land, a dispute needs two colonists to argue. The base rule is that the world has to be still enough to change.

proc
cancel
(reason)

Stops the incident before it finished, returning anything it was holding.

Cancellation is not a failure and does not produce a result: nothing happened, so there is nothing for the pacing state to learn from.

proc
execute
()

Does whatever the incident does. The base incident is a contract, so it does nothing.

proc
is_finished
()

TRUE once the incident has stopped, either way.

proc
release_reservations
(reason_code)

Gives back everything still held. Safe to call more than once; the second call has nothing to return.

proc
reserve_credits
(amount, reason_code)

Holds credits against this incident, taking them out of the settlement's account.

Reserved rather than spent, so that an incident interrupted halfway does not cost the colony money for something it never received. Every movement is a ledger entry either way.

proc
reserve_resource
(resource_id, amount, reason_code)

Holds a resource quantity against this incident, on the same terms as credits.

proc
resolve
(outcome, pressure_change)

Records what the incident did. Returns TRUE only if this call is the one that decided it.

Idempotent by refusal rather than by overwriting: a second resolution is a bug somewhere upstream, and paying its rewards again would be a worse outcome than ignoring it.

proc
select_target
()

Chooses whatever this incident acts on. Concrete incidents override; the base acts on nothing in particular.

proc
set_state
(new_state)

Moves to new_state if that is a legal step. Returns TRUE when it happened.

Legal means the next step forward, or a jump to cancelled from anywhere that has not finished. Skipping ahead is refused rather than runtimed, because two systems racing to advance an incident should end with the first one winning, not with a stack trace.
